# Independent review: tracking validation metric contract

Task `tracking-metric-review-001`, 2026-09-29. Reviewed the registered [contract](tracking_metric_design.json), the `validation/tracking.py` diff, [implementation note](TRACKING_METRIC_IMPLEMENTATION.md), new `tests/test_tracking_validation.py`, and the lead-owned [test ledger](tracking_metric_test_runs.json) and [static checks](tracking_metric_static_checks.json). The reviewer made no test, tracker, source or network invocation.

**Disposition: accept the minimal metric repair, with the legacy lifetime diagnostic explicitly scoped.** `validate_tracking` now uses one deterministic per-frame, one-to-one greedy assignment of retained predictions to GT that is present at that frame. The spatial condition is `distance <= match_radius_px`, closing the prior radius-plus-one leak. An unmatched prediction is FP in both contracts. A prediction matched to ineligible GT is a valid **all-presence** TP, but it is counted as `ignored_ineligible_matches`, neither TP nor FP for detectable-only precision. Detectable TP and FN are restricted to the same eligible GT frames. Eligibility with a movie is the *observed* local coat peak crossing `coat_floor`, not a noiseless truth threshold; no-movie fallback marks all present GT eligible and labels that choice.

The `all_presence` block exposes every GT-present frame, including entirely ineligible or missed events. Its `gt_events_ever_matched` and top-level `gt_structures_detected` come from these valid framewise matches, rather than the old median-position lifetime association; a spatially close prediction outside the GT presence interval cannot recover an event. Explicit rates are `None` at their own zero denominators, with F1 computed directly as `2TP/(2TP+FP+FN)`; compatibility top-level scalar rates use the documented zero fallback and now mean all-presence. The top-level event fraction likewise has the zero fallback when no GT exists. `metric_contract_version` makes the migration visible. Repository caller search found only the sweep, CLI and existing orchestration test; sweep P/R/F1 and event recovery now have explicit all-presence/detectable labels, and CLI identifies its all-presence score.

The remaining `lifetime_pairs` logic is still nearest median-position matching and may include a track that does not validly recover an event. It is labeled `lifetime_pairs_scope="legacy positional median-track diagnostic"` and marked as such in CLI output; it must not be read as the new event-coverage denominator or a biological lifetime estimate. This is an acceptable boundary for the requested minimal repair. The implementation did not alter the detector, linker, `Track` or `run_tracking` APIs; the lead's AST comparison and Ruff F check support that scope.

The lead's first targeted invocation passed **15 tests** (new fixture regressions plus existing orchestration) with exactly **one** instrumented `run_tracking` movie, within the three-invocation/three-movie budget. Fixtures cover mixed eligible/ineligible matches, missed ineligible frames, all-visible and no-movie equivalence, empty and unmatched cases, temporal nonoverlap, duplicate predictions, conditional precision with a true FP, and the exact spatial boundary. The sweep's final explicit event-fraction label was a later output-key-only edit. The lead's [label audit](tracking_metric_label_review.json) shows that reversing only that literal key rename exactly recovers the tested full-source SHA-256; all tested validator logic is byte-identical. Final Ruff F also passes. One test invocation/one tracker movie is therefore the complete execution record, with no need to rerun for a key label; a later substantive scoring edit would need fresh validation.
